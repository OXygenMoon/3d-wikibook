## 自动集成检查

`npm test` 的 7 项集成测试通过，使用独立临时数据目录，不修改本地用户数据：

1. 默认管理员登录、错误密码、HttpOnly Cookie、敏感字段不返回，以及管理员接口权限。
2. 批量注册、自动分配空工位、重复名单整批拒绝。
3. 创建班级区域、间距调整、班级重叠／公共区冲突检查、工位重新分配。
4. 只有主人可以在自己工位附近编辑；家具数量、坐标及持有范围校验；文件持久化；换工位时搬迁布置。
5. 公共区域必须实际抵达；贴纸保存；机房任务和排行榜积分；任务不能重复领取。
6. 昼夜设置、在线心跳、聊天、退出撤销会话、非公开文件不可下载。
7. 并发导入不能重复注册同一账号，不能重复分配工位。

`npm run build` 通过，最新界面／模型／Three.js 资源已生成至 `dist/`。界面、场景、公共区和服务脚本语法检查通过。

- 创建班级区、调整间距、导入名单与设置昼夜的前置流程均取得成功页面与落盘结果。
- `community-complete-evidence.json`：**66／66 步完成**，覆盖管理员账号、昼夜、个人工位、添加和保存家具、实体贴纸墙发布、排行榜区域、机房任务、钓鱼、背包、退出及新注册普通账号的独立编辑。捕获窗口内控制台事件为 0。
- `community-pond-evidence.json`：18／18 步完成，白天池塘场景。
- `community-mobile-evidence.json`：390×844 窄屏操作与截图；确认登录后保留虚拟摇杆和跳跃／奔跑控制。
- `community-production-evidence.json`：交付服务 `http://127.0.0.1:4173/`，11／11 步完成，管理员登录与打开真实工位编辑，控制台事件为 0。
- 可见浏览器额外确认：实际拖动绿植后 X/Z 值变更，保存成功；刷新后账号和家具保留；普通用户没有管理入口；机房设计任务领取的真实活力出现在殿堂榜单。

最初 Chrome Dev 158 的捕获出现点击未分发的情况，临时事件跟踪显示点击未到达页面。相同场景在稳定版 Edge 和内置浏览器可正常执行。此诊断不记为成功测试；前期未完成的捕获保留用于排查。家具平面图的按下变换／拖动重绘冲突已修正，并经实际拖动和后续完整流程验证。临时调试日志已移除。

## 当前范围

功能运行在本机 Node.js + Three.js 服务上。每个班级最多 8×8、社区总计最多 256 工位；这个上限是当前配置约束，不代表已通过 256 人同时在线压测。窄屏已做浏览器验证，未在真实手机设备或所有 GPU 上检查。课程平台、语音、图片上传和多机部署未纳入本次要求。

`preview-community.png` 为交付服务的夜间家具编辑预览，`preview-pond.png` 为白天荷花池预览。README.md 包含操作与数据存放说明。
