# 课程平台对接契约

当前已实现本地班级任务与教师确认后的奖励闭环。尚未配置真实外部课程平台，没有对外部系统发送请求或验证第三方成绩数据。

## 账号映射

本地账号以 `users.id` 作为稳定标识；`username`、姓名和工位编号都不能作为跨平台不可变标识。外部账号映射应保存：

```json
{
  "provider": "目标平台标识",
  "externalUserId": "平台侧不可变用户编号",
  "localUserId": "本地 users.id",
  "verifiedBy": "配置映射的管理员编号"
}
```

`provider + externalUserId` 唯一。本地账号不存在、班级不匹配或映射未由管理员确认时拒绝发奖。名单 CSV 继续用于本地开户，不从姓名自动猜测跨平台身份。

## 完成事件格式

```json
{
  "version": 1,
  "eventId": "平台侧唯一事件编号",
  "provider": "目标平台标识",
  "type": "task.completed",
  "externalUserId": "平台侧不可变用户编号",
  "externalTaskId": "平台侧任务编号",
  "completedAt": "2026-10-20T08:00:00+08:00"
}
```

外部任务需要管理员预先映射到一个本地班级任务。事件不包含可直接采用的积分、家具或模型奖励；奖励以本地任务已发布配置为准。`provider + eventId` 去重，同一账号同一任务只发奖一次。签名失败、映射失败、班级不匹配、任务未配置时拒绝处理并记录原因。

## 实际接入前需要的信息

需要目标平台的官方接口、授权方式、测试账号、真实用户与课程编号规则，以及可验证的完成事件或成绩查询方式。确定平台后再实现对应适配器、签名验证、幂等事件存储和失败重试；当前没有可供外部调用的匿名发奖接口。

跨平台端到端验收需要从测试平台实际完成一次任务，验证本地只发奖一次，并验证重复、乱序和无效事件。当前只完成契约设计，本地任务流程已有自动验证。
