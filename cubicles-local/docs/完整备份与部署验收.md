# 完整备份与部署验收

## 备份内容

`npm run db:backup -- manual` 生成 `backups/community-<时间>-manual-<编号>/`，包含：

- `snapshot.json`：社区、账号、班级、模型、建筑、工位、课堂、会话、聊天、审计，加来源班级、身份、小组、成员关系，共 17 张表。
- `models/`：社区状态引用的全部 GLB 文件。
- `manifest.json`：文件路径、大小与 SHA-256。模型缺失时整次备份失败，不发布不完整目录。

数据库快照使用只读、可重复读事务；备份过程不加载并回写应用内存状态，不执行数据库重置或迁移。快照之后发生的模型删除可能使本次备份失败，可重试。默认保留最近 30 个完整备份，旧 JSON 备份继续保留。

备份目录权限为 700，文件权限为 600。备份包含会话令牌和密码哈希，应按账号数据保护。

## 本地 PGlite

先停止 `npm start`，再执行备份、恢复或演练，完成后重新启动。PGlite 的进程锁会拒绝第二个进程打开同一目录；进程异常退出后可以自动识别并清理失效锁。

```sh
npm run db:backup -- manual
npm run db:restore-drill
npm start
```

## PostgreSQL / Docker

PostgreSQL 支持应用运行时执行只读备份与隔离恢复演练。

```sh
docker compose exec app npm run db:backup -- manual
docker compose exec app npm run db:restore-drill
```

恢复到正在运行的库前必须停止应用。写进程通过 PostgreSQL advisory lock 互斥，维护脚本不会覆盖仍在运行的应用。

```sh
docker compose stop app
docker compose run --rm app npm run db:rollback -- /app/backups/<完整备份目录>
docker compose up -d app
```

恢复先校验全部文件，恢复前自动生成当前库备份，再用事务替换全部业务表，并修复消息序列。已有模型内容一致时复用；冲突时拒绝覆盖。事务失败会恢复原有表并清理本次新增文件。旧版 13 表／4 表完整目录与单个 JSON 的回滚仍受支持；JSON 只恢复社区状态，不含模型文件、会话和聊天。新备份用 `domainStorageVersion: 2` 标记，缺少来源身份表时拒绝恢复；旧备份中的新增身份域为空。

## 可重复部署验收

```sh
npm run test:deployment
```

需要 Docker daemon 和 `docker-compose` 命令；只有 Compose 插件时可将相应入口提供为 `COMPOSE_COMMAND` 可执行文件。脚本在 `.tmp/` 建立隔离数据，创建独立 Compose 项目，验证：

1. 从源码构建生产镜像。
2. PostgreSQL 启动、首次导入旧 JSON 与已有 GLB。
3. 登录、聊天、工位模型引用和私有模型下载。
4. 生成完整备份，将 PostgreSQL 快照恢复到隔离 PGlite，逐表、逐文件比对。
5. 重启容器，原 Cookie 继续有效，聊天与模型仍保留。

结果写入 `.tmp/acceptance/deployment-check.json`，不会被浏览器测试清空。脚本只删除自己创建的测试容器、测试数据卷和临时目录，不操作实际社区数据。

这证明本机容器环境可迁移运行；另一台物理机器尚未验收，需要提供相应机器环境。
