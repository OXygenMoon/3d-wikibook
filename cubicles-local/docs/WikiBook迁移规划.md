# WikiBook → 3D 学习平台迁移规划

日期：2026-10-20。

## 已确认的终态

用户已明确：**最终由 3D 平台独立承接 WikiBook 全部功能，分阶段迁移**。保留 WikiBook 为永久业务主站、只做 API 展示壳或嵌入旧站，不满足这一目标。

最终交付包括数据、文件、业务规则、接口、权限、管理功能和后台任务，不只复制页面。每名学生拥有独立工位；学习成果与贴纸获取规则可以驱动 3D 家具、物品和模型资格奖励。旧站的只读访问、双跑比较或桥接仅是过渡手段。

独立不等于全部重写为 Node.js。可以把已有 Python 领域服务迁入新平台的部署包，与 Three.js／Node 服务共同运行；但最终部署不得依赖旧 WikiBook 进程、源码目录、数据库或域名。是否保留 Python 服务应在契约与依赖盘点后确定，优先保留经过验证的业务语义，不为统一语言重复实现奖励引擎。

| 容量 | 需在授权数据盘点后确认实际人数与班级 | 当前单世界最多 256 工位、单区域最多 8×8 | 超容量必须明确分世界／班级实例，不得静默漏掉学生或仅放大人数上限 |

## 完整范围，不因首批实现而缩减

1. 身份与治理：学生、班级、分组、账号权限、管理员、会话、强制改密、通知、公告及确认。
2. 学习内容：Wiki、书籍、页面、历史、笔记、便签、标签、附件、导入导出、订阅和可见范围。
3. 学习过程：学习时段、番茄钟、任务、作业、提交、评分、课堂／自习／学习小组及其权限。
4. 编程：题库、测试数据、提交、判题队列与 worker、作业、比赛、题解、语法卡和排行；保留隔离执行边界。
5. 数据分析：项目、工作区、协作、执行／AI 后台任务、证据与成果文件，明确执行沙箱和依赖。
6. 成就与资源：贴纸、荣誉徽章、进度、贴纸册、贴纸墙、原创设计、资源发放、书签、壁纸、明信片、主题等。
7. 社交与活动：关注／学友、个人空间、作品、消息、商店、兑换、抽取、小游戏、钓鱼、农场等现有模块。
8. 运维：媒体与上传、异步任务、实时协作、配置、日志、备份恢复、接口兼容、部署与数据保留。

以上按现有源码整理，最终边界以逐路由、逐数据实体、逐文件类型、逐 worker 的验收矩阵为准。不得因为模块暂时不展示在 3D 场景中就将其视为已迁移或直接删除。

## 学生与工位

- 稳定关系为原始学生 ID → 平台用户 ID → 世界／班级 → 唯一工位 ID，同一账号多次同步或多会话登录不得新建第二个工位。
- 分组与班级分别保留，不能将学习小组直接改成行政班级。未分班、重复学号、账号冲突和超容量学生必须进入异常清单，不能静默跳过。
- 工位所有权与当前坐标分离；转班调整位置但保留背包、模型资格和布置，冲突需可审计处理。
- 毕业、停用或退班保留身份历史与资产，是否回收位置单独制定规则，不做不可逆自动删除。
- 全量导入先 dry-run，报告学生数、班级数、需要的工位数、冲突和空间规划；验证通过并明确确认后才写真实目标库。

## 贴纸条件与 3D 奖励

### 同一事实、同一条件引擎、多种奖励

学习记录 → 原有条件评估／成就发放 → 可审计的奖励资格 → 平台背包 → 工位摆放。

统一复用条件标识、阈值、目标参数、AND／OR、时间范围、去重口径、时区、审核状态和成就依赖；不在浏览器重新判断是否达标。原有手动发放、隐藏／秘密信息、限量、有效期与序列号语义也需盘点，不能只复刻“计数达到阈值”。

配置时区分两种关系，不能混为一谈：

- **关联实际贴纸获取**：以真实 `UserBadge` 归属／发放记录为证据，例如“获得指定贴纸后解锁书架”。历史已获贴纸是否补发由迁移配置决定。
- **共用获取条件**：3D 奖励引用同一条件组，可与贴纸同时或独立发放，例如同样达到一组学习要求后解锁家具。是否沿用贴纸限量和有效期必须显式配置，不能因为条件达标就假定拿到了限量贴纸。

3D 奖励还需明确是永久模型使用资格、数量家具还是消耗型兑换；当前模型资格是布尔解锁，不能冒充支持限量物品实例。具体贴纸到 3D 模型的美术资源和映射表待配置，不凭贴纸名称自动猜测。

### 可靠性

- 奖励流水记录学生、奖励定义、来源成就／条件、证据、规则版本、周期和时间。
- 同一学生、奖励定义和周期建立唯一约束；规则版本仅用于追溯，修改文案或阈值不能意外变成重新发奖的机会。
- 库存、资格与奖励流水原子提交；跨服务采用事务 outbox／可重放收件箱，避免先通知后回滚、丢事件和重复消费。
- 历史补发先输出预览清单；全量补发、重复导入、进程中断恢复和并发处理都不得重复发奖。
- 重新判题、撤销审核、改规则、贴纸撤销后的 3D 资产处理须有明确策略，不能擅自删除学生已摆放的物品。
- 当前社区钓鱼活力与 WikiBook 的学习积分／贴纸条件并非同一指标，不能直接相加或互相换算。

## 分阶段实施与验证

| 阶段 | 交付 | 通过标准 |
| --- | --- | --- |
| M0 全量基线 | 静态清单、隔离运行时 URL map、模型／数据库／文件／后台任务盘点、接口与权限矩阵 | 每个源条目都有目标方案和状态；核对静态与运行时差异，确认授权数据源和备份 |
| M1 身份与工位 | 账号／班级／分组映射、认证兼容、容量规划、幂等导入与 dry-run | 每名范围内学生恰有一个工位；重复导入不增号，冲突可追溯，转班保留资产，越权被拒绝 |
| M2 贴纸与 3D 奖励 | 迁入原规则引擎、贴纸／历史归属、映射配置、发放账本、背包与摆放 | 同一组脱敏样本在旧／新系统条件结果一致；历史补发、重复事件、回滚和并发不重复发奖 |
| M3 逐域迁移 | 内容与学习 → 作业／OJ → 数据分析 → 资源／社交／活动及后台 | 每个域的数据关联、接口契约、权限、文件、后台任务及关键用户流程通过，不以 HTTP 200 代替业务验证 |
| M4 独立切换 | 完整部署包、最终增量与冻结窗口、独立运行和恢复演练 | 停止旧站并阻断其网络后仍能登录、学习、判题、获奖、摆放；数据逐域对账，备份可恢复，回退方案可执行 |

M1／M2 是首批闭环，不是将“全部功能”缩为贴纸同步。实施期间只在隔离数据上开发和验证，未经明确确认不改写旧站真实学生记录、不覆盖现有 3D 社区数据、不更换用户密码。
