# 数据结构与运行边界

## 当前持久化结构

数据库共 17 张应用表：

| 表 | 内容 |
| --- | --- |
| `community_state` | 版本、修订号、贴纸、昼夜设置等社区元数据 |
| `users` / `zones` | 账号、背包、积分、权限与班级区域 |
| `model_assets` / `world_buildings` | 模型目录与公共世界建筑 |
| `office_layouts` | 工位家具与自定义位置 |
| `class_tasks` / `class_submissions` | 课堂任务与学生提交 |
| `class_announcements` / `reward_grants` | 班级公告与幂等奖励记录 |
| `sessions` / `messages` / `audit_log` | 会话、聊天与操作审计 |
| `source_classes` / `source_identities` | 来源平台班级与用户的稳定映射 |
| `source_groups` / `source_memberships` | 来源学习小组与成员关系 |

业务记录以独立行保存，主键、关联和常用筛选字段为类型化列，灵活属性保留在每行 JSONB 中；不是所有属性都已完全关系化。`community_state.data` 不再重复保存业务数组。应用当前仍载入业务快照到内存，保存时只写入变化记录，不能据此声称已具备海量数据按需查询能力。

旧数据启动时自动迁移：先保存迁移前逻辑备份，再在事务中拆表。`0001` 迁移含延迟检查的关联与唯一约束，使一次事务内移动账号／替换记录可行。旧 JSON 和旧四表目录备份兼容恢复。

## 事务与失败恢复

- 课堂审核、奖励记录、背包和活力在同一次状态事务中提交；任务与账号组合唯一，重复确认不会重复发奖。
- 写入串行排队并捕获独立快照；数据库错误回滚后，内存恢复至最后成功提交版本。
- 回滚会使已在途的旧状态请求失效，以 503 要求重试，避免后来的旧快照覆盖恢复结果。
- 故障注入测试覆盖奖励插入失败、业务记录约束失败、排队与异步旧请求，另在真实 PostgreSQL 重跑相关集成测试。
- 操作审计在业务提交后另行写入，不保证与业务记录原子提交；它不是财务级不可丢失的事件账本。

## 会话与运行模式

位置心跳默认每 2 秒合并写入，`SESSION_PERSIST_INTERVAL_MS=0` 可恢复每次即时持久化。登录、退出及互动冷却状态即时写入；正常关闭会冲刷剩余心跳。进程突然崩溃可能丢失最近一个批次的位置，但不会因此撤销已提交的任务奖励。退出后待处理心跳不得重建已删除会话。

PGlite 使用进程文件锁，PostgreSQL 使用专属连接的 advisory lock，均只允许一个应用写进程。PostgreSQL 可在线只读备份；PGlite 维护时需停服。多实例仍缺少共享在线状态、缓存失效和跨进程并发协调，当前明确不支持水平扩容。

客户端断网显示连接状态，恢复后重试心跳与失败模型请求。会话失效则退回访客并清理旧账号的私有模型。模型不可见时不保留其 GPU 缓存。桌面约 40 米、窄屏约 24 米范围内显示工位细节并按需加载模型；远处保留基础场景与碰撞。

## 本机测试画像

以下为隔离数据测试，不向真实社区导入测试账号。

| 场景 | 结果 / 证据 |
| --- | --- |
| 30 账号 PGlite 普通模型 | 心跳 p95 9.66 ms，工位保存 p95 65.20 ms；`.tmp/acceptance/performance-30-final.json` |
| 30 账号 PostgreSQL 普通模型 | 心跳 p95 12.02 ms，保存 p95 138.40 ms；`.tmp/acceptance/performance-30-postgres-final.json` |
| 30 账号、30 个独立约 1.45 MB / 6 万三角形模型 | PGlite 心跳 p95 4.84 ms，保存 p95 63.56 ms；`.tmp/acceptance/performance-30-stress.json` |
| 浏览器：56 工位、30 个独立 6 万三角形模型、约 30 个其他在线角色 | 4 倍 CPU 限速、90 帧采样，p95 约 19 ms；可见约 166 万三角形、约 1100 draw calls；`.tmp/acceptance/browser-profile.json` |
| 窄屏与断网 | Chromium 390×844 布局、触控按钮、断网恢复和会话撤销流程通过；不等同于真实手机验收 |
| Docker / PostgreSQL | 源码镜像构建、导入、Cookie／聊天重启保留、完整跨驱动恢复通过；`.tmp/acceptance/deployment-check.json` |

测试机器 GPU 是 Apple M3 Max，CPU 限速不会模拟低端 GPU、真实移动浏览器、网络带宽、贴图显存压力或全天运行。普通压测模型只有 36 个三角形；重模型无贴图。以上结果是特定工作负载的快照，不能相互比较推导稳定性能增益，更不是对全部合法上传模型的性能保证。

建议将 **30 人单班、小规模受控试用** 作为下一步验证目标，而非已验收的生产服务承诺。默认上传上限仍为 20 MiB、30 万三角形、2000 节点；大贴图与最坏合法模型组合需额外验证。

## 尚未完成的外部验收

1. 第二台机器：需要部署目标与访问方式，本机 Docker 不代替异机验收。
2. 真实低配电脑／手机：需要设备，当前只有桌面浏览器模拟和 CPU 限速证据。
3. 真实班级：需要教师和学生参加，验证实际网络、模型组合及完整课时稳定性。
4. 外部课程平台：只完成账号映射与事件契约，未实现真实平台适配；需要目标接口和授权。

进入对外部署前，还应更换默认账号密码、配置 HTTPS／安全 Cookie、安排备份保存位置与恢复演练责任人。不要直接将当前默认本地开发配置暴露到公网。
