# P0 工程地基

日期：2026-10-19。范围对应路线图的 P0：数据库、模块拆分、会话持久化、
可观测性、备份恢复、Docker Compose 与浏览器冒烟测试。

## 1. 现在具备什么

| 能力 | 实现 |
| --- | --- |
| 数据库 | PostgreSQL（生产）/ PGlite（本地与测试，嵌入式 Postgres） |
| 迁移 | Drizzle ORM + `drizzle/0000_*.sql`，启动时自动执行 |
| 旧数据迁移 | `scripts/db-import.mjs` 一次性导入 `community.json`，导入前自动备份 |
| 回滚 | `scripts/db-rollback.mjs` 恢复任意备份 |
| 会话 | `sessions` 表持久化，重启后仍可继续使用原 Cookie |
| 消息 | `messages` 表持久化，重启后聊天记录保留 |
| 审计 | `audit_log` 表记录管理员、工位、任务、钓鱼等关键动作 |
| 健康检查 | `GET /healthz`、`GET /readyz` |
| 日志 | Pino 结构化 JSON 日志，带 `requestId` |
| 错误监控 | 设置 `SENTRY_DSN` 后启用 Sentry；未设置时保留结构化错误日志 |
| 备份 | `npm run db:backup`，按天保留最近 30 份 |
| 恢复演练 | `npm run db:restore-drill`，在隔离临时数据库中导入并逐字段校验 |
| 一键启动 | `docker compose up --build`（Postgres + 应用） |
| 测试 | 26 项单元/集成测试 + 8 条 Playwright 冒烟 |
| 静态检查 | `node --check` + ESLint（未定义变量、危险 API、重复键等） |
| CI | `.github/workflows/ci.yml`：Postgres 服务、检查、测试、构建、E2E |

## 2. 模块结构

```
server.mjs                     仅负责 HTTP 启动、静态资源、健康检查、错误边界
src/server/
  config.mjs                   环境变量与路径
  logger.mjs                   Pino 结构化日志
  monitoring.mjs               Sentry（可选）
  http.mjs                     JSON、Body、Cookie、错误、MIME、安全头
  db.mjs                       Postgres / PGlite 驱动与迁移
  db/schema.mjs                Drizzle 表结构
  store.mjs                    community_state、导入、备份、恢复
  session-store.mjs            sessions 表与内存缓存
  message-store.mjs            messages 表
  audit.mjs                    audit_log
  auth.mjs                     密码、Cookie、会话、角色校验
  domain.mjs                   工位/区域/世界布局的领域规则
  resources.mjs                GLB 上传与下载
  api.mjs                      API 路由分发
  routes/
    auth-routes.mjs            登录、会话、退出、个人资料
    world-routes.mjs           世界快照、心跳、工位家具
    social-routes.mjs          聊天、贴纸
    learning-routes.mjs        机房任务、排行榜、钓鱼
    admin-routes.mjs           区域、名单、分配、昼夜、世界布局、模型
```

HTTP 契约保持不变，前端 `src/main.js` 与 `src/community-ui.js` 没有因为 P0 改写。
这是刻意的：先替换地基，再改学习功能。

## 3. 数据库策略：P0 的桥接设计

P0 没有一次性把 20 多张业务表全部拆完，而是：

- **已经规范化**：`sessions`、`messages`、`audit_log`。
- **暂时保留为文档**：`community_state.data`（JSONB），保存 users、zones、
  officeStyles、buildings、modelAssets、stickers 等现有社区状态。
- **原因**：P0 的目标是“可靠持久化 + 可迁移 + 可回滚”，不是重写领域模型。
  全部规范化会把 P0 变成 P1，增加回归风险。
- **约束**：当前是单写者模型。同一时间只应运行一个应用实例；多实例部署
  需要先完成 P1 的领域表拆分或引入乐观锁/行锁。
- **下一步**：P1 按 `users / zones / offices / layouts / assets` 逐表迁移，
  `community_state` 只保留迁移期兼容读取。

这不是长期架构，而是明确标注的过渡层。`docs/工程地基.md` 与代码注释都记录
了这个决定，避免以后误以为 JSONB 是最终方案。

## 4. 运行方式

### 4.1 本地开发（无需 Docker）

```sh
cp .env.example .env      # 可选；不复制也会用默认值
npm start
```

默认使用 PGlite，数据在 `.local-data/pglite/`。首次启动如果存在
`.local-data/community.json` 且数据库为空，会自动导入并保留原文件。

### 4.2 PostgreSQL

```sh
docker run -d --name cubicles-db \
  -e POSTGRES_USER=cubicles \
  -e POSTGRES_PASSWORD=cubicles \
  -e POSTGRES_DB=cubicles \
  -p 5432:5432 postgres:16

DATABASE_URL=postgres://cubicles:cubicles@127.0.0.1:5432/cubicles npm start
```

启动时自动执行 `drizzle/` 中的迁移。

### 4.3 Docker Compose

```sh
cp .env.example .env
# 修改 POSTGRES_PASSWORD / DEFAULT_ADMIN_PASSWORD
docker compose up --build
```

- 应用：<http://127.0.0.1:4173/>
- Postgres 数据：`pgdata` 命名卷
- 社区文件：`./.local-data` 挂载到 `/data`
- 首次启动：数据库为空时自动导入 `/data/community.json`
- 备份：`./backups` 挂载到 `/app/backups`
- 定时备份（可选）：`docker compose --profile ops up backup`

如果本机没有 Compose 插件，请先安装 Docker Desktop 或
`docker-compose`。Compose 文件本身是标准格式，可用
`docker compose config` 校验。

## 5. 数据导入、回滚与备份

### 导入

```sh
npm run db:import -- --file .local-data/community.json --dry-run
npm run db:import -- --file .local-data/community.json --force
```

导入前会把当前数据库状态写到 `backups/community-<timestamp>-pre-import.json`，
同时保留原始文件副本 `backups/source-<timestamp>.json`。

### 回滚

```sh
npm run db:rollback -- backups/community-2026-10-19T13-32-30-955Z-smoke.json
```

回滚前会再生成一份 `pre-restore` 备份，避免二次误操作。

### 备份

```sh
npm run db:backup -- manual
```

默认保留最近 30 份。生产环境建议用 cron 每天执行：

```cron
0 3 * * * cd /path/to/cubicles-local && npm run db:backup -- scheduled
```

### 恢复演练

```sh
npm run db:restore-drill
```

流程：当前库导出 → 写入临时备份 → 在隔离的临时 PGlite 数据库中导入 →
逐字段比对 → 删除临时目录。只有全部一致才输出 `ok: true`。

## 6. 可观测性

- 每个请求有 `X-Request-Id`，错误响应带 `requestId`。
- 日志为 JSON 行，包含 `method`、`path`、`status`、`ms`、`ip`。
- `/healthz` 检查数据库连通性，数据库不可用时返回 503。
- `SENTRY_DSN` 存在时启用 Sentry；否则只写结构化日志，不阻塞启动。
- `COOKIE_SECURE=true` 用于 HTTPS 部署。

## 7. 测试

```sh
npm run check        # 语法 + ESLint
npm test             # 26 项，默认 PGlite；设置 DATABASE_URL 则使用 Postgres
npm run build
npm run test:e2e     # 8 条 Playwright 冒烟
```

Playwright 覆盖：

1. 管理员登录与 HttpOnly Cookie。
2. 进入三维世界、HUD 与小地图初始化。
3. 编辑并保存家具，刷新后仍保留。
4. 抵达贴纸墙并发布贴纸。
5. 管理员在世界编辑器中移动班级并保存。

本地首次运行 Playwright 时，如果默认浏览器缓存不可写，可使用：

```sh
PLAYWRIGHT_BROWSERS_PATH="$PWD/.tmp/playwright-browsers" \
  npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH="$PWD/.tmp/playwright-browsers" npm run test:e2e
```

`playwright.config.mjs` 会自动优先使用 `.tmp/playwright-browsers`。

## 9. 已知边界

1. 单写者：`community_state` 为单行 JSONB，禁止多实例同时写。
2. 心跳写库：每个在线账号每秒更新一次 `sessions`。30–100 人可接受，
   更大规模需要合并写入或引入 Redis。
3. 备份是逻辑备份（JSON），不是 `pg_dump` 物理备份；跨版本恢复前先跑
   `db:restore-drill`。
4. 模型文件仍在本地磁盘 `/data/models`，未接对象存储。
5. Docker 镜像构建依赖外网拉取 Node 基础镜像；离线环境需提前导入镜像。
