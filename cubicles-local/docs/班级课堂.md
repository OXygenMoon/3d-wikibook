# 班级课堂

入口：登录后打开“我的账号 → 班级课堂”。

## 角色与班级

管理员在“管理后台 → 账号与分配”选择账号角色，并为教师选择一个或多个负责班级。至少保留一个管理员。教师只能发布和管理所负责班级的内容；学生只看到自己班级的任务与自己的提交。

教师可以发布班级公告、导入本班 CSV 名单、将本班学生调整到空闲工位。CSV 与管理员名单使用相同表头：`账号,密码,姓名,班级`。班级名称必须与当前班级一致；跨班级、重复账号或容量不足均整批拒绝。

## 任务流程

教师打开“发布新任务”，填写名称、要求和可选截止时间。学生填写说明或 HTTP/HTTPS 作品链接，提交后等待教师确认。教师可以反馈并退回修改，或确认完成；确认完成后学生不能覆盖已完成提交。教师还可以关闭和重新开放任务，超过截止时间的任务仍禁止提交。

每次重新提交会增加版本号。教师打开旧版本后，如果学生已更新内容，服务端拒绝确认并要求刷新。重复确认同一完成记录不会重复执行完成动作。

## 学习奖励与作品

发布任务时，教师可配置 0–1000 活力、每种 1–5 件目录家具，以及最多 5 个需要任务解锁的共享模型。管理员先在模型的使用范围中选择“完成班级任务后解锁”。确认完成后自动发放，学生在背包中查看并摆放模型。已有工位仍受边界、总数量和个人资格校验。

班级课堂显示个人学习记录和班级活力榜。学生提交时可以主动勾选“完成后展示到本班作品墙”；没有勾选的作品只供本人和负责教师查看。外部课程平台尚未接入，预留约定见 `课程平台对接契约.md`。

## 验证

`tests/classroom.test.mjs` 覆盖跨班级权限、角色提升拦截、管理员保留、名单导入、工位归属、任务关闭、链接限制、提交版本冲突、教师确认与重启保留。

`tests/e2e/classroom.spec.mjs` 通过实际界面验证：管理员设置教师 → 教师发布公告和任务 → 学生提交 → 教师确认 → 学生看到完成与反馈。
