# 格子社区：可定制空间与后续扩展

> 实施更新：账号、管理后台、班级区域、工位分配、家具背包与编辑、昼夜亮灯、实体公共功能区现已实现。当前使用方式以 README.md 为准。下文保留长期扩展设计。

## 定位与当前边界

这个原型可以扩展为“班级拥有公共区域、学生拥有个人工位、学习活动发生在功能区”的持续在线社区。可定制范围可以覆盖内容、家具、个人空间、区域规划和社区规则。

当前默认创建 24 个工位，工位数量、班级区域位置与间距可在管理员后台调整；单社区当前配置上限为 256 个工位。已实现账号与独立布置持久化、班级名单导入、所有权校验、背包家具摆放、在线亮灯、机房任务、殿堂榜单、实体贴纸墙和荷花池。

长期容量仍取决于设备、模型复杂度、场景加载方式和同时在线人数，需要按目标规模压测。课程系统对接、复杂奖励规则、图片贴纸和更多休闲功能仍属于后续扩展。

## 账号与工位归属

每个工位可以绑定一个账号。建议将“工位地点”和“用户摆放方案”分开存储：工位记录地点、区域与主人；摆放方案记录家具、位置、旋转和可编辑属性。学生换班或换工位时，可以搬走自己的布置；原工位可以重新分配。

建议首版规则：一个学生在一个班级内拥有一个有效工位；可参观其他工位，只有主人能修改个人布置；教师可管理本班分配，社区管理员可调整公共布局。服务器根据登录身份校验归属，不能只靠前端隐藏编辑按钮。

家具编辑器可以支持拖拽、旋转、网格吸附、碰撞提示、撤销、保存和恢复默认。班级公共墙体、道路、边界由教师或管理员编辑，个人家具在自己工位的许可范围内摆放。

## 班级分区与管理员布局

支持“社区 → 班级区域 → 工位”的组织方式。管理员创建或导入一个班级，选择地图中的区域，设置工位行列、间距、朝向与通道，再按名单批量分配。班级人数变化时可以扩建区域、增添空工位或重新排序。

区域除了平面地块，也可以是独立楼层或室内场景。一个学校可以拥有多个班级区，公共机房、荣誉殿堂、池塘则由多个班级共享。教师可配置班级入口、公告和活动时间。

## 在线状态与夜间亮灯

建议区分：

- **在线**：名牌有绿点，主人角色在社区中活动。
- **暂离**：名牌变为柔和黄点，角色可进入休息动作；不等同离线。
- **离线**：保留工位布置，名牌置灰；若展示坐姿替身，应明确标为离线展示。
- **专注／忙碌**：显示自选状态，聊天可以留下留言。

昼夜与在线状态独立计算。例如社区当地时间进入夜晚后，在线用户的工位台灯、电脑屏幕和名字边缘亮起；离线工位保留装饰，以较低亮度展示。用户在线但位于池塘时，工位仍能显示“在线，正在池塘”。关闭标签页后通过服务器心跳超时更新状态，短暂断网先显示重连，避免灯光频繁闪烁。

大量工位亮灯时，优先使用发光材质、屏幕亮度和廉价光晕表达；只为镜头附近少量灯具启用真实光源和阴影。不能给每个远处工位都添加实时阴影灯。

## 物品建模与条件发放

家具可以持续制作成 GLB 模型，按统一尺寸、原点和朝向入库。每种物品还需要配置缩略图、可摆放位置、碰撞范围、占地、交互行为和性能等级。模型只解决外观；可发放、可持有和可摆放需要物品数据系统。

发放条件示例：首次加入获得基础桌椅；完成指定课程获得显示器；连续参与活动获得植物；作业达标获得限定台灯；班级共创达成目标获得区域雕塑；比赛获奖获得可摆放奖杯。规则由服务器判定，记录发放原因与次数，避免刷新页面重复领取。

首版可以使用“物品目录 → 发放规则 → 用户背包 → 摆放实例”四层结构。物品可设置绑定账号、期限、数量和可回收性。教师还可手动向指定班级或学生发放奖励。

## 大型功能区如何工作

| 功能区 | 场景表现 | 需要连接的实际功能 |
| --- | --- | --- |
| 机房 | 成排电脑、讲台、投影屏幕、座位 | 电脑打开练习任务、课程、代码编辑器或作业入口；教师配置内容 |
| 排行榜殿堂 | 奖杯台、领奖台、荣誉展柜、班级旗帜 | 真实学习／活动数据、周期结算、班级／个人维度、历史荣誉 |
| 贴纸墙 | 可贴图和留言的公共墙面 | 图片／文字上传、贴纸位置、班级可见范围、置顶、审核与撤回 |
| 池塘 | 水面、钓位、鱼、钓竿、昼夜环境 | 钓鱼状态机、鱼种与背包、图鉴、活动任务和奖励规则 |
| 项目展厅 | 展台、海报、可走入的主题房间 | 学生作品、项目链接、讲解、评论和收藏 |
| 讨论室 | 围坐座位、白板、共享屏幕 | 班级小组、文字／语音会话、协作内容和预约 |

大场景应按区域加载。室外社区、机房和殿堂可以共用账号、背包和状态服务，但各自加载当前需要的模型，避免所有场景同时占用浏览器内存。

在线状态属于短期会话数据；账号归属、班级成员、区域分配、家具背包和摆放方案属于持久化数据。多人会话不能替代账号系统，客户端活力值也不能直接作为正式奖励的权威依据。

## 建设顺序

1. **身份与归属**：真实账号、教师／学生／管理员角色、班级名单、区域和工位分配。
2. **个人空间闭环**：模型目录、背包、摆放编辑器、服务端保存与所有权校验。
3. **社区生命感**：在线／暂离／离线、昼夜、在线亮灯、串门与留言。
4. **学习与激励**：课程／任务事件接入、奖励规则、排行榜殿堂和作品展厅。
5. **共创与休闲**：贴纸墙、池塘、活动、宠物、节日主题及更多场景。

第一阶段可以先用“一个班级、一块区域、每人一个可分配工位”验证完整流程，再逐步扩展整个社区。本轮已完成账号、分区、背包布置、昼夜和四个实体功能区域，详细验证见 VALIDATION.md；以上仍包含可以继续推进的长期设计。
